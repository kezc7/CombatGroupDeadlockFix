DESCRIPTION (BBCode - paste into the Nexus description editor)
[size=4][b]Combat Group Deadlock Fix[/b][/size]
Fixes a vanilla engine freeze (a deadlock) in Skyrim AE [b]1.6.1170[/b] that can happen as a fight breaks out.

[b]New:[/b] the freeze was traced in a real game, and the fix has been checked against the game's code and tested against a model of the game's lock. Please report your results, good or bad, with the log file (see below).

[size=3][b]The freeze[/b][/size]
When combat starts, the game locks that fight's [i]combat group[/i] (the list of who is fighting whom). It then waits to update another NPC's knowledge of the fight.

At the same moment, that NPC's own AI update holds its knowledge list while it looks for enemies. For each one it asks the same combat group "is this person one of your targets?".

Each side waits for the lock the other holds. The game's locks never give up, so the game freezes, usually with no crash log.

It was found with a debugger snapshot of a frozen game, and confirmed in the game's code.

[size=3][b]The fix[/b][/size]
That one "is this one of your targets?" check is replaced by the same check, done the same way, with one difference: if it can't get the combat group's lock within half a second, it gives up and answers "not a target" for that check.
[list]
[*]In normal play the lock is held for a tiny fraction of that, so the check behaves exactly as before.
[*]In the freeze, it gives up, which lets both sides carry on. While the same stuck lock remains, the rest of that AI update gets the same answer at once, so the hitch stays short.
[*]The worst case is a hitch of about half a second instead of a hard freeze.
[*]Nothing else in the game is changed.
[/list]

[size=3][b]Known side effect[/b][/size]
At the moment of a give-up, one NPC may not count someone as an enemy, so it may not react to them right then. The next AI update asks again.

This only happens after a combat group has been locked for half a second, which in the unmodified game would have been a freeze or a long stall. If you see NPCs ignoring enemies after a "gave up" line in the log, please report it.

[size=3][b]Safety[/b][/size]
[list]
[*]Only loads on Skyrim AE 1.6.1170. On any other version, SKSE skips it.
[*]Before changing anything, it fingerprints all of the game code it relies on: the check itself and the game's lock functions. If anything differs (another mod changed the same code), it leaves the game alone and says so in its log.
[*]Nothing is written to your save, so it can be added or removed at any time.
[/list]

[size=3][b]Requirements[/b][/size]
[list]
[*]Skyrim AE [b]1.6.1170[/b]
[*]SKSE64 for 1.6.1170
[*]Address Library for SKSE Plugins
[/list]
Not for SE 1.5.97, other AE versions, or VR.

[size=3][b]Installation[/b][/size]
Install with your mod manager, or copy [i]SKSE\Plugins\CombatGroupDeadlockFix.dll[/i] into [i]Data\SKSE\Plugins[/i]. Load order doesn't matter (there is no plugin file).

[size=3][b]Compatibility[/b][/size]
Works alongside other freeze and crash fixes, including Skyrim Freeze Fix NG and Interrupt Package Deadlock Fix, which fix different freezes.

Combat AI mods that work through records and game settings don't conflict with it, though none have been specifically tested yet. An SKSE plugin that changes the same game function would make this one refuse to install, and it says so in its log.

[size=3][b]Log and troubleshooting[/b][/size]
[code]Documents\My Games\Skyrim Special Edition\SKSE\CombatGroupDeadlockFix.log[/code]
[list]
[*][b]installed at SkyrimSE+803DF0[/b]: working.
[*][b]not installed[/b]: the lines above it say which game code differs; nothing was changed.
[*][b]gave up after ... ms waiting for a combat group's lock[/b]: a combat group was locked for half a second or more. This is most likely the freeze this mod fixes.
[*][b]waited ... ms ... then got it[/b]: a slow moment the fix didn't need to step in for.
[*]No log at all: SKSE didn't load it; [i]skse64.log[/i] says why (expected on other game versions).
[/list]
Still freezing in combat? Not every combat freeze is this one. Please post the log and a freeze dump.
